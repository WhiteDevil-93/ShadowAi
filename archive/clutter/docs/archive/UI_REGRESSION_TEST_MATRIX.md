# UI Regression Test Matrix - UI/UX Orchestrator

This matrix covers comprehensive regression testing for the UI/UX Orchestrator, ensuring compliance with Material 3, accessibility standards, and system integration best practices.

| Test Case ID | Requirement Category | Preconditions | Steps | Expected Result | Priority |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **COMP-001** | Component: Scaffold & App Bars | App is launched on a standard phone device. | 1. Verify the main screen structure. 2. Interact with the TopAppBar (e.g., tap a navigation icon). | The screen uses a Scaffold correctly. The TopAppBar is visible, adheres to Material 3 specs, and does not overlap content. | High |
| **LAYOUT-001** | Layout: Screen Size & Orientation | App is launched on a tablet device. | 1. Rotate the device from Portrait to Landscape. 2. Resize the app window (multi-window mode). | The layout adapts correctly to both Portrait and Landscape orientations. All critical elements (conversation, input field) remain visible and functional without clipping. | High |
| **INTERACT-001** | Interaction: Execution Chip | An execution task is currently running (e.g., a long-running AI plan). | 1. Single tap the active execution chip/pill. 2. Long-press the active execution chip/pill. | 1. A non-modal bottom sheet/dialog with execution details and logs opens. 2. A context menu with "Cancel" or "Stop Execution" options appears. | High |
| **ERROR-001** | Error State: Inline Pill & Retry | A transient, non-critical error occurs (e.g., a minor API timeout). | 1. Observe the error presentation. 2. Tap the "Retry" affordance. | The error is displayed as an inline, dismissible pill using the Material 3 error color role. The pill includes a clearly labeled "Retry" action button. Tapping "Retry" attempts the operation again. | High |
| **ERROR-002** | Error State: Critical Dialog | A critical, blocking error occurs (e.g., authentication token expired). | 1. Observe the error presentation. 2. Acknowledge the error. | A modal dialog is triggered, requiring user acknowledgment. The dialog uses the Material 3 error color role and includes a "Fix" or "Acknowledge" action. | High |
| **IME-001** | Keyboard: IME Padding & Overlap | The primary input field is focused, and the soft keyboard is visible. | 1. Verify the position of the input field. 2. Scroll the conversation thread. | The input field and its container correctly apply imePadding(). The soft keyboard does not overlap or obscure the input field or the Send button. | High |
| **INSETS-001** | System Insets: Status/Navigation Bars | App is run on a device with visible system status and navigation bars (e.g., a phone with 3-button navigation). | 1. Verify the TopAppBar's position. 2. Verify the BottomAppBar/Input field's position. | The TopAppBar uses statusBarsPadding(). The bottom content uses navigationBarsPadding() to avoid drawing under the system bars. | High |
| **M3-001** | Material 3: Color & Elevation | Observe various components (Scaffold, Dialogs, Buttons). | 1. Check button colors (Primary, Secondary, Error). 2. Open a modal dialog. | All components strictly adhere to Material 3 color roles. Modal dialogs and bottom sheets use appropriate Material 3 elevation tokens (e.g., tonalElevation). | Medium |
| **M3-002** | Material 3: Typography | Observe all text elements (Headlines, Body text, Labels). | 1. Compare text sizes and weights against the design spec. | All text elements use the defined Material 3 typography scale (e.g., display, headline, title, body, label). | Medium |
| **MOTION-001** | Motion: State Transitions | Interact with a component that changes state (e.g., a button from disabled to enabled, a loading spinner to a checkmark). | 1. Trigger the state change. 2. Observe the animation. | The state change is animated using Material 3-compliant motion curves and durations (e.g., Compose's animate*AsState). | Medium |
| **MOTION-002** | Motion: Failure Condition | Trigger a failure condition (e.g., a failed execution). | 1. Observe the UI reaction. | The error state is accompanied by a distinct, non-jarring motion (e.g., a subtle shake or color pulse) to draw attention. | High |
| **PERF-001** | Performance: Jank & Smoothness | Perform rapid scrolling and trigger complex animations (e.g., opening a large bottom sheet). | 1. Use a performance monitoring tool (e.g., Android Studio Profiler). 2. Visually inspect for stuttering. | All animations and transitions maintain a smooth frame rate (target 60 FPS) with no noticeable jank or dropped frames. | Critical |
| **A11Y-001** | Accessibility: Screen Reader | Enable a screen reader (e.g., TalkBack). | 1. Navigate through the entire screen using swipe gestures. 2. Interact with the primary input field and buttons. | All interactive elements are correctly labeled and focusable. The screen reader announces the purpose and state of each component clearly. | High |
| **A11Y-002** | Accessibility: Touch Targets | Inspect all interactive elements (buttons, chips, toggles). | 1. Measure the size of the touch target area for all interactive elements. | All interactive elements meet the minimum touch target size requirement of 48dp x 48dp. | High |
