#### 2. Plan.kt ✅ COMPLETED

**Issues Fixed:**
- **Mutable State in Data Class (HIGH):** Refactored PlanNode to be immutable
  - Removed `var` modifiers from status and result
  - Added helper methods: withStatus(), withResult(), withFailure()
  - Plan uses val for nodes list

- **Empty Node List Allowed (MEDIUM):** Added validation in Plan init block
  - require(nodes.isNotEmpty()) { "Plan must contain at least one node" }
  - Version field validation: require(version >= 1)

- **Version Field Not Sealed (LOW):** Version is now validated to be >= 1

**Implementation:**
```kotlin
data class Plan(
    val version: Int = 1,
    val nodes: List<PlanNode>
) {
    init {
        require(nodes.isNotEmpty()) { "Plan must contain at least one node" }
        require(version >= 1) { "Plan version must be at least 1" }
    }
}

data class PlanNode(
    val id: String,
    val action: DeviceAction,
    val dependencies: List<String> = emptyList(),
    val status: NodeStatus = NodeStatus.PENDING,  // Now val, not var
    val result: String? = null                     // Now val, not var
) {
    fun withStatus(newStatus: NodeStatus): PlanNode = copy(status = newStatus)
    fun withResult(newResult: String): PlanNode = copy(status = NodeStatus.COMPLETED, result = newResult)
    fun withFailure(errorMessage: String): PlanNode = copy(status = NodeStatus.FAILED, result = errorMessage)
}
```

#### 3. PlanParser.kt ✅ COMPLETED

**Issues Fixed:**
- **org.json Usage (HIGH):** Migrated to Kotlinx Serialization
  - Replaced JSONObject/JSONArray with kotlinx.serialization.json
  - Uses Json.parseToJsonElement() for parsing
  - JsonObject and JsonArray for element access

- **No Stack Overflow Protection (HIGH):** Added depth limit
  - MAX_DEPTH = 50 in companion object
  - json.maxDepth = MAX_DEPTH in Json configuration

- **Size Check Bypass (MEDIUM):** Use byte length instead of char length
  - `jsonString.toByteArray().size > MAX_JSON_SIZE` instead of `jsonString.length`

- **Double JSON Serialization (MEDIUM):** Avoid re-serializing
  - Pass action JSON directly using `actionElement.toString()` instead of re-parsing

- **Inefficient Cycle Detection (MEDIUM):** Optimized algorithm
  - Iterative DFS with coloring algorithm (WHITE/GRAY/BLACK)
  - Early exit on cycle detection
  - O(V+E) complexity instead of potential O(V*E)

**Implementation:**
```kotlin
class PlanParser @Inject constructor() {

        private const val MAX_STRING_LENGTH = 10000
    }

        ignoreUnknownKeys = false
        isLenient = false
```
